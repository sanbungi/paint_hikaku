# paint_hikaku

ペンタブ（またはマウス）でお手本を模写し、重ね合わせと診断で「どこがどう違うか」を学ぶトレーニングアプリです。  
上手さの点数付けではなく、位置・大きさ・傾き・抜け・はみ出し・線の揺れといった **系統的なクセ** を返します。

<img width="5111" height="2853" alt="image" src="https://github.com/user-attachments/assets/2be3b980-2ea9-430c-917d-f684788e6ac0" />


Electron（Node.js + HTML/CSS）製のデスクトップアプリです。採点エンジン（ラスタ化・比較・診断・パース）は GUI 非依存の JavaScript モジュールで、Node.js 単体でテストできます。

対象: **Windows 10/11 x64**（主対象）、Ubuntu 22.04・24.04 amd64（AppImage）。

## ダウンロード

- **最新のビルド**: GitHub の [Actions](../../actions/workflows/ci.yml) で成功した実行を開き、Artifacts の `paint_hikaku-windows-exe` をダウンロードします（ZIP の中に exe が入っています）。
- **リリース版**: `v1.2.3` 形式のタグを push すると、検証済みの exe / AppImage と `SHA256SUMS` が GitHub Releases に公開されます。

| ファイル | 内容 |
|---|---|
| `paint_hikaku-<版>-windows-x64-portable.exe` | インストール不要。ダブルクリックで起動 |
| `paint_hikaku-<版>-windows-x64-setup.exe` | インストーラー（スタートメニュー登録・アンインストール対応） |
| `paint_hikaku-<版>-linux-x86_64.AppImage` | Ubuntu 用。`chmod +x` して起動 |

コード署名はしていないため、Windows の SmartScreen で「詳細情報 → 実行」が必要な場合があります。

## できること

- なめらかなストローク（Catmull-Rom 補間 + 筆圧で幅。ペンタブの筆圧は Pointer Events で直接取得）
- 組み込み図形: 直線・円・楕円・矩形・正三角形・正五角形・十字・S 曲線
- 線練習: 2点を結ぶ・斜め3本・円3つ
- 立体: 立方体・直方体・円柱・六角柱・四角錐・円錐・球
- パース: 1点／2点／3点透視・アイソメ、水平角・上下角・距離・地平線、補助線と隠れ線（ガイドは採点対象外）
- **人物（3D）**: 内蔵のデッサン人形、または自分の **VRM モデル（0.x / 1.0）** を読み込み、サンプルポーズを選んで配置。3D のまま軽く動かして構図を決め（左ドラッグ=回転、右ドラッグ=ずらす、ホイール=大きさ、スライダーでも可）、「この構図で描く」で輪郭と折れ目を採点用の線にしてから描く。床グリッドと目線（採点対象外）も表示
- **ポーズエディタ（別ウインドウ）**: 人形や VRM の頭・胸・腰・手・ひじ・ひざ・足・視線の点をつかんでドラッグするだけでポーズが付く（フルボディ IK）。腰を下げれば足を床に残したまましゃがみ、手を遠くへ引けば背骨と肩も伸びる。手足のピン留め、Shift+ドラッグで回転、角度スライダーでの微調整、左右反転・片側コピー、アンドゥ。作ったポーズは名前を付けて保存でき、メイン画面のポーズ一覧に並ぶ（JSON で書き出し・読み込みも可）
- **下絵の書き出し**: ポーズエディタの今の視点（カメラの向き・パース）のまま、陰影・シルエット・線画（輪郭と折れ目）・外接箱（画面上の箱と中心線／立体のパース箱）・骨格（アタリ）・床グリッドと目線を PNG に書き出す。人物に合わせた切り抜きか今の視点のまま、縦横比（3:4・A4・正方形・16:9 など）、長辺 1024〜4096px、陰影の濃さ・線の太さ・白／透明背景を選べ、1 枚に合成するほか、レイヤーごとの透過 PNG（ペイントソフトのレイヤー用）やクリップボードへのコピーもできる
- **画像からポーズ**: 写真やイラストから MediaPipe Pose Landmarker で関節位置を推定し、そのままポーズにする（左右反転も可）。推定はすべて手元の PC 上で行い、画像は送信しない。推定モデル（約 9 MB）は初回にダウンロードするか、手元のファイルを選ぶ
- 画像をお手本にできる（カラーのまま表示。採点は暗い線をマスク化。PNG / JPEG / BMP / WebP / GIF。ウィンドウへのドラッグ＆ドロップにも対応）
- 答え合わせ: 重ね（青=お手本 / 赤=自分 / 緑=一致）・差分・距離ヒートマップ
- 診断コメント（日本語）と参考スコア（IoU、Chamfer 距離）
- 位置合わせなし（デフォルト）または重心合わせ
- 見本と紙で同期するグリッド（2 / 3×3 / 4×4）と外接箱
- 上下または左右の配置
- 記憶模写（見本を隠す）とチラ見
- セッションをローカル JSON に記録し、同じ題材のクセ傾向を表示

## 開発

Node.js 22 以上が必要です。

```bash
npm ci                        # three.js / three-vrm は npm run build で src/renderer/vendor/ にまとめる（start・test:gui・dist では自動）
npm start                     # 起動
npm start -- path/to/lineart.png   # 自分の線画を開いて起動
npm test                      # 単体・シナリオ回帰（ウィンドウ不要）
npm run test:gui              # 実ウィンドウを操作する GUI 回帰（Linux の画面なし環境では xvfb-run -a を前に付ける）
npm run dist:win              # Windows 用 exe（portable / setup）を dist/ に生成
npm run dist:linux            # AppImage を dist/ に生成
```

構成:

| パス | 役割 |
|---|---|
| `src/engine/` | 採点エンジン（GUI 非依存。D 版から移植） |
| `src/main/` | Electron メインプロセス（ウィンドウ、ファイルダイアログ、履歴 JSON の保存） |
| `src/renderer/` | 画面（HTML/CSS/JS）。描画・入力・表示切替 |
| `src/renderer/figure/` | 3D 人物（デッサン人形、VRM 読み込み、ポーズ、カメラ、描画） |
| `src/renderer/pose-editor/` | ポーズエディタ（別ウインドウ。`pose-preload.cjs` の IPC だけでアプリとつながる） |
| `src/engine/ik.js`, `posing.js`, `posefit.js` | IK ソルバー、ドラッグ操作、画像のランドマーク → ポーズ（three.js 非依存、Node でテスト） |
| `src/engine/underdrawing.js` | 下絵の書き出し（レイヤー合成、外接箱などのガイド図形、切り抜き枠） |
| `test/unit/`, `test/gui/` | 回帰テスト。詳細は [test/README.md](test/README.md) |

## 操作

ウィンドウ左側でお手本を選び、中央キャンバスで模写します。上のツールバーは普通のボタンです。

| 操作 | 方法 |
|------|------|
| お手本 | 左リストをクリック（図形／線練習／立体／サンプル画像） |
| 画像 | 「画像を開く…」またはウィンドウへドロップ（カラー表示） |
| 人物（3D） | 左リストの「デッサン人形」か「VRM モデル…」。`.vrm` はウィンドウへのドロップや起動時の引数でも開ける |
| ポーズ | 「人物（3D）」欄のリスト（立ち・Tポーズ・コントラポスト・歩き・走り・座り・しゃがみ・考える・見上げて手を伸ばす、と自作ポーズ） |
| ポーズエディタ | 「人物（3D）」欄の「ポーズエディタ…」で別ウインドウが開き、今のモデルとポーズを編集する。`npm start -- --pose-editor` でエディタだけを起動することもできる（下表） |
| 構図 | 調整中は見本が 3D 表示になり、紙はロックされる。左ドラッグ=選んだツール（回転／移動／ズーム。ペンタブ向けにボタンで切替）、右ドラッグ=移動、ホイール=大きさ（20〜800%。100% を超えるとレンズのズームで顔や手のアップにできる）。「この構図で描く」で確定、「構図・ポーズを変える」で戻る。同じポーズで構図だけ変えたときは描いた線が残る |
| 見本の表示 | 陰影＋線 / 陰影のみ / 線のみ。「内部の線も採点する」を外すと輪郭だけを採点 |
| 描画 | キャンバスをドラッグ（ペンタブはマウス相当） |
| ツール | 見本と紙の間に「ペン（B）」「消しゴム（E）」「手のひら（H）」。Space を押しながら／中ボタンでドラッグしても表示を動かせる。ペンの消しゴム側（裏返し）でも消せる |
| 線の太さ・色 | 同じ場所のスライダーと色ボタン（右端で任意の色）。太さは採点にも使い、色は表示だけ |
| 表示倍率 | −／＋／全体（Ctrl+-／Ctrl++／Ctrl+0）、またはホイール（ポインター位置を中心に拡大）。最大 1200%。見本と紙は常に同じ範囲を表示 |
| アンドゥ / クリア / 答え合わせ / もう一度 / 記録 | 見本と紙の間のボタン（Ctrl+Z / Ctrl+Enter / Ctrl+S） |
| 答え合わせ | 右ペインに重ね表示と診断。そのあとも続けて描き足し・消しゴム・アンドゥができ、もう一度「答え合わせ」で採点し直す（前回の結果は「加筆中」として残る） |
| 重ね／差分／ヒート／スライド | 右のコンボボックス |
| 重心合わせ | チェックボックス（形だけ見たいとき） |
| 記録 | 「記録」。左下の履歴と、同じ題材の傾向 |
| 配置 | ツールバー「上下 / 左右」（既定は左右。ウィンドウは自由にリサイズ） |
| 設定・診断欄 | 「題材・設定」「診断」で開閉。狭い画面では初期状態で非表示。内容はスクロール可能 |
| グリッド | なし / 2分割 / 3×3 / 4×4（採点対象外） |
| 外接箱 | お手本の外枠をガイド表示 |
| 記憶模写 | 見本を隠す。チラ見で約2秒だけ表示 |
| 筆圧 | ペンタブの筆圧で線幅が変わる。マウスは Shift=細、Ctrl=太 |

記録先:

- Linux: `~/.local/share/paint_hikaku/sessions/`
- Windows: `%APPDATA%\paint_hikaku\sessions\`

`PAINT_HIKAKU_DATA_DIR` を設定すると保存先を変更できます。テストでは必ず一時ディレクトリを使用します。保存先・JSON 形式は D 言語版と同じなので、以前の記録もそのまま読み込めます。

## CI / Release

- push ごとに、テスト（Ubuntu: 単体・GUI 回帰・起動確認）と Windows exe の作成（単体テスト、portable exe のビルド、パッケージ済み exe の起動確認）を **並行** して実行します。exe は実行ページの Artifacts `paint_hikaku-windows-exe` から取得できます。`.md` だけの変更では実行しません。
- `vMAJOR.MINOR.PATCH` タグでは、インストーラー exe と AppImage も作り、すべての検証が通ったら exe・AppImage・`SHA256SUMS` を Release へ公開します。
- ブランチ保護を設定する場合のチェック名: `Test`、`Windows exe`。

### ポーズエディタの操作

| 操作 | 方法 |
|------|------|
| 部位を動かす | 色の点を左ドラッグ（青=左半身、橙=右半身、緑=体幹、紫=視線）。画面に平行な面の上を動く。奥行きは視点を回してから動かす |
| 部位を回す | Shift を押しながら点をドラッグ（腰=体の向き、頭=顔の向き、手足=手首・足首、ひじ・ひざ=腕・脚のねじり） |
| ピン留め | 手・足の点をダブルクリック、または選んで P。ピン留めした手足は、ほかを動かしてもその場に残る（足は最初からピン留め） |
| 視点 | 空いた所を左ドラッグ=回す、右ドラッグ=動かす、ホイール=ズーム。正面(1)・横(3)・上(7)・全身(F) |
| 微調整 | 「選択中の部位」の X / Y / Z スライダーで、ボーンの角度を直接変える |
| 元に戻す | Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z） |
| 保存・送る | 名前を付けて「保存」（Ctrl+S）。「メイン画面で使う」で保存してメイン画面のポーズにする |
| 画像から | 「画像を開く…」またはウィンドウへドロップ。人物が 1 人写った画像を推奨。推定後も点で直せる |
| 下絵を書き出す | 同名の欄でレイヤーと枠を選ぶ（プレビューあり。「今の視点のまま」は書き出す範囲を点線で表示）。「PNG で保存…」=合成した 1 枚、「レイヤーごとに保存…」=選んだフォルダーの中に新しいフォルダーを作り `00 合成.png`・`01 陰影.png`…`07 線画.png` を保存、「コピー」=クリップボードへ |

自作ポーズは `<記録先の親フォルダー>/poses.json`、推定モデルは `<記録先の親フォルダー>/models/` に保存します（`PAINT_HIKAKU_DATA_DIR` を設定するとその下）。

## 設計の要点

- 比較はベクトル一致ではなく **同じ論理解像度（768²）のラスタマスク**。なぞり訓練で厳しすぎないようにしている。表示サイズや表示倍率を変えても採点解像度は変わらない。
- 紙の上の自分の線はベクトルで描くので、拡大しても滲まない（採点は 768² のマスク）。消しゴムも 1 本のストロークとして記録し、アンドゥで戻せる。
- デフォルトは位置合わせなし。ズレ自体が学習対象。重心合わせは「形は近いが場所が違う」を切り分けるときだけ使う。
- 写真お手本はカラー表示。採点は輝度の暗い部分を線とみなす（透明部分は紙として扱う）。
- 3D 人物は three.js / three-vrm で 768² に描画し、深度と法線のバッファから「輪郭（背景との境）」「重なりの境（深度の段差）」「折れ目（法線の急な変化）」を線として抜き出して採点マスクにする。ポーズは VRM の正規化ボーンに角度で与えるので、内蔵の人形と VRM で同じポーズが使える。どのポーズでも足が床に着くよう接地させる。
  構図の調整中は画面へ直接描くだけ（1 フレーム数 ms）で、採点用の描画（色・深度・法線の 3 パスと読み戻し、線の抽出）は確定時に 1 回だけ行う。表示の切替や「内部の線」の ON/OFF・お手本の線の太さは確定時のバッファから作り直すので再描画しない。
- VRM モデルは同梱していない。各モデルの利用条件に従って使い、モデル名と作者は画面に表示する。GPU が使えない環境では Chromium のソフトウェア描画（SwiftShader）で 3D を表示する。
- ポーズエディタの IK は、手足に **解析的な 2 ボーン IK**（ひじ・ひざは蝶番関節として一方向にだけ曲がり、曲がる向きはひじ・ひざの点＝ポールで決める）、背骨・首・届かない手の追従に **CCD**（関節ごとの重みと角度制限つき）を使う。腰を動かしたあとはピン留めした手足を 2 ボーン IK で元の位置へ戻す（簡易フルボディ IK）。ドラッグ中は毎回ドラッグ開始時の姿勢から解き直すので、動かすほど崩れることがない。VRM の正規化ボーン（初期回転が単位）の上で解くので、人形と VRM で同じ仕組みが使える。
- 画像からのポーズは、ランドマークを角度に変換する（Kalidokit 方式）のではなく、**IK のターゲット**として使う。骨の向きは画像から、骨の長さはモデルから取り、ひじ・ひざの点で曲がる面を決めるので、体形の違う VRM でも破綻しない。見えなかった部位は自然な姿勢のまま残す。
- ポーズエディタは「半分分離」した別ウインドウで、アプリとは決まった IPC（現在のモデルとポーズを受け取る／ポーズを送り返す／自作ポーズの保存）だけでつながる。単独でも起動でき、保存したポーズは次にアプリを開いたときに使える。
- 下絵の書き出しは、エディタの描画器でモデルだけを色・深度・法線の 3 パスで描き、メイン画面の採点用と同じ方法（`edges.js`）で線画を作る。ガイド（外接箱・骨格・床と目線）は同じカメラで投影して描く。「人物に合わせて切り抜く」は小さな試し描きで人物の範囲を求め、カメラのビューオフセットで切り抜くので、パースは見ている視点のまま変わらない。合成とガイドの図形は `src/engine/underdrawing.js`（GUI 非依存）。
- MediaPipe（`@mediapipe/tasks-vision`、Apache-2.0）の実行部分（WebAssembly）は同梱し、推定モデル `pose_landmarker_full.task` は利用者の操作で初回だけダウンロードして SHA-256 を照合する。ネットにつながらない環境では手元の `.task` ファイルを選べる。
- 画面はレンダラープロセスの素の HTML/CSS/JS（バンドラーなし）。Node.js の機能はプリロード経由の最小限の IPC（画像を開く・履歴と自作ポーズの読み書き・ポーズモデルの取得）だけに限定し、`contextIsolation` と `sandbox` を有効にしている。
